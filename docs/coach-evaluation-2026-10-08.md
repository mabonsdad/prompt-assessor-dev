# Prompt Coach and Workflow Coach evaluation — 8 October 2026

## Method

Ten synthetic workplace prompts were sent through **both** live modes (a trial answer followed by that mode's critique). Six concern film/TV production. The first five established a baseline; their results were reviewed before the coaching instructions were changed. The remaining five tested the revised instructions. All ten were then retested after the structural revision, with one transient HTTP 503 retried successfully. Later, narrow freshness and capability refinements were regression-tested on case 3. No real documents, private records, or attachments were used. Public web search was off for the comparable ten-case set; an additional, web-enabled Workflow Coach run checked case 3.

The review asked whether each mode (1) shows the user the material omission without inventing one, (2) produces a clear, reusable prompt, (3) gives observable steps in execution order, (4) places suitable tools/connectors and human decisions at the right stage, and (5) states task-specific guardrails. Simple requests should not be inflated into workflows. “Thinking process” here means checkable work and decisions, not a request for hidden chain-of-thought.

Run the synthetic cases again with `node scripts/evaluate-coaches.mjs 1 10 /tmp/prompt-assessor-evaluation.json`. For a focused source-check, run `node scripts/evaluate-coaches.mjs 3 3 /tmp/prompt-assessor-wage-web.json --web`; this enables search only for the Workflow Coach critique, not the trial answer or Prompt Coach. The script calls the live API and incurs model usage.

## What the first five revealed and what changed

- Workflow Coach initially gave cases 1 and 2 full six-section rewrites, even while recognising that no workflow was needed. It now returns a short mode-fit response and no rewrite for genuinely simple, stable, low-stakes requests.
- The case 3 trial answer originally stated the **April 2025 £7.55** apprentice rate as “now”; [GOV.UK lists £8 from April 2026](https://www.gov.uk/national-minimum-wage-rates). Prompt Coach did not receive the trial answer, so it could not identify this specific failure. It now receives the trial answer as unverified material, and the trial-answer instructions prohibit a remembered historic number as a substitute for a current answer. An optional web-enabled critique verified the current figure and correctly labelled the trial answer's no-web limit as a capability issue, not a user-prompt flaw.
- In case 4, Prompt Coach initially allowed “reasonable assumptions” about shoot constraints, which could conceal infeasibility. It now asks for blocking source/constraint gaps and marks production sign-off.
- Workflow Coach identified many relevant gaps but did not distinctly label guardrails or reliably show the order of tool use and human approval. Its improved prompt now has dedicated Goal, Sources, Tools, Guardrails, Process, Human decisions, and Output sections. Process steps are observable and ordered: clarify, gather evidence, use available tools for deterministic checks, apply a method/rubric, pause for human approval where needed, then produce or carry out the authorised output. Prompt Coach uses a separate **Guardrails** point only when material, keeping cases 1 and 2 light.
- In the first post-change meeting test, Prompt Coach still allowed reminders to confirmed owners without approval. The final instruction now requires explicit human approval before sending, assigning, signing, publishing, spending, or changing an external system. Case 10 passed on retest.

On the last full comparable run, both simple cases needed no rewrite; all eight nontrivial Workflow Coach rewrites contained a distinct Guardrails section and numbered observable steps. They specify a human decision rule or checkpoint proportionate to the task; the general public-rate question needs no approval, but a personalised entitlement check first requires eligibility details. The consequential production, casting, financial, legal, and messaging cases all stop before the relevant decision or action. The resulting prompts use square-bracket placeholders rather than filling unknown facts, and recommend tools/connectors conditionally rather than claiming access.

## Limits and teaching value

- The trial-answer step has **no web search**, even when Workflow Coach search is checked. Search is available only to the critique step. Without it, the safe answer to a current-rate question may be “I cannot verify it”; with it, the critique can identify and source the missing current fact. This contrast is a useful training exercise about capabilities and verification, but the UI should not imply the trial answer searched.
- These tests did **not** exercise actual file uploads, live drive/Slack connectors, scheduling or calculation tools, data privacy controls, or a real multi-turn human approval. The coaches recommend these steps; this app does not enforce or execute them. A good recommended prompt is not itself a secure automation.
- Complex Workflow Coach rewrites remain fairly long, especially on mobile. They are more structured, but a future UI could offer a collapsed “key gaps” view alongside the full reusable prompt.
- Model output varies across runs. The committed fixture and these scenarios are a regression set, not a guarantee. One transient API 503 occurred and succeeded on retry; reliability should be monitored separately from advice quality.

The revisions follow current [OpenAI prompt-engineering guidance](https://developers.openai.com/api/docs/guides/prompt-engineering) on representative evals, explicit task/context/output contracts and tool instructions; [reasoning guidance](https://developers.openai.com/api/docs/guides/reasoning-best-practices) on clear goals and verifiable outcomes rather than demanded hidden reasoning; and [safety guidance](https://developers.openai.com/api/docs/guides/safety-best-practices) on source checking, adversarial testing, and human review for consequential uses.

An eleventh follow-up case tests [advice-only connector and human-gate flow coaching](advice-only-flow-evaluation-2026-10-08.md).
